Restricted plan format for the controller-owned Freya compiler:
Root: initial_node, nodes (object keyed by name), optional system_prompt.
Every node has matching name and node_type. Public names begin with a letter or
underscore and contain letters/digits/underscores; bg_* is reserved.

conversation fields: name,node_type,task_message,routing_prompt,on_enter,
on_enter_first_entry_only,extraction_schema,transitions,max_node_turns,
max_turn_transition. No other fields. on_enter is {type:llm}, {type:tts,text:...}
or {type:silent}. Transitions may target public plan nodes only.
Extraction entries: name,type,description,min_confidence, optional enum_values,
validation_pattern,max_retries,extraction_prompt. Types are string,integer,float,
boolean,date,datetime,name,phone_number. Write only public proposed-input variables.
Custom extraction_prompt must include the kit's extractor.speech,
extractor.conversation.last-10,extractor.type_preamble,extractor.variables_list
placeholders. Use documented template substitution for read-only dialogue values.

Transitions: {target_node,description,condition}. Intent conditions use
{operator:matches_intent,description:...}; fallback {operator:always}.
Variable comparisons use outer {logic:or,conditions:[...]}; nested and/or groups
are permitted. Operators: equals,not_equals,greater_than,less_than,contains,
is_set,is_not_set. Avoid duplicate routes to the same target with incompatible
conditions. Every conversation fallback and failure route targets a public node.

Action placeholder:
{name,node_type:"guard_action",action,inputs:{semantic_field:public_variable},
success_node,blocked_node,failure_node}. All three route targets are required.
Inputs are variable names, not literals, API schemas, code or protected state.
Supported roles and input keys:
verify_identity: field,answer
get_account: none
stage_promise: product_id,amount,date
commit_promises: none; optional product_id when confirming separately
stage_note: product_id,reason
finalize_notes: none
stage_transfer: queue
commit_transfer: none
schedule_callback: date,time
close_call: none; optional outcome,reason for language-derived identity disposition

A guarded close_call is required; authored end_call nodes are forbidden.
Its controller-owned terminal is silent. Source-required farewell, app advice or
other concluding explanation needs an authored speaking conversation on each
applicable path before close_call. The compiler does not add that dialogue. Do not
claim a final close was recorded before its API result or speak after termination.
The compiler owns protected bg_state/bg_route values and all internal nodes. A
compiler success route means observed API success or completed local staging as
appropriate. Blocked/failure routes do not establish that any bank write occurred.

Read-only runtime view: use {{bg_facts}} in model task/system instructions for
current identity progress, next factor, immediate-result hint, routing/action
status and recorded-action counts. Every guard step refreshes this protected JSON;
no authored extraction may write it. Raw bg_state/bg_body/result variables,
customer_id and automatic operation-result variables cannot be templated. now
may be read. Never place bg_facts in authored on_enter speech/TTS.
Raw protected values also cannot appear in condition.variable reads. The string
routing_prompt may read {{bg_facts}} explicitly; task_message is not visible to
the routing model, so put needed routing context in routing_prompt/transitions.

internal_action_references.products contains product_ref IDs needed for proposed
action inputs; these are internal and must never be spoken. position is policy
processing order; returned_position is original account order. product_states
uses positions and distinguishes staged from recorded writes. Internal refs may
also carry proposal_constraints (normalized type, band, floor/cap cents and the
policy business deadline), resolution_status and remaining_failure_attempts.
Use only available constraints to propose terms; blocked/unavailable constraints
never authorize a write. These internal fields are not narration permission and
contain no assertion of persuasion attempts remaining. Account narration
is blocked unless active account_disclosure_fields explicitly declares approved
returned scalar fields. A legacy array requires every listed field for every
product. The supported conditional object has common (an array of fields required
for every product) and by_product_type (source-defined product types mapped to
arrays required only for that selected type). Names, type codes and permissions
come from the frozen source/API bindings; do not invent type-specific exceptions.
Then account.products contains only common and selected-type approved fields and
positions. Missing required fields block narration; unrelated API extras never
become permitted merely because another product type may disclose them. Use these
approved displays for human wording; never expose internal IDs or API extras.
Quarantined/unavailable views cannot authorize further bank actions or imply
unknown writes succeeded.

If the source requires shared-deadline adjustment dialogue, use the available
approved proposal constraints to explain the change and obtain fresh agreement
before the final guarded commitment. The guard owns calculations and consent;
the authored dialogue owns required explanations. Do not narrate raw protected
state, internal IDs or unavailable constraints, or infer a shared-deadline rule
from this transport reference.
