Freya kit v3 format summary, derived from the pinned workflow/tools references.

Root: initial_node (normal node key), system_prompt, nodes (object keyed by node
name); optional global_nodes. Every node has name equal to its key and node_type.
Names use letters/digits/underscores, beginning with a letter or underscore.
Omit agent_config. No null anywhere in workflow JSON. No top-level lifecycle tools.

conversation: task_message describes this node's dialogue only. Routing does not
see task_message; use transitions/routing_prompt. on_enter is {type:llm},
{type:tts,text:...}, or {type:silent}. Extraction is an array of objects with name,
type, description, min_confidence, optional enum_values/validation_pattern.
Extraction types: string,integer,float,boolean,date,datetime,name,phone_number.
Use string routing flags. A custom extraction_prompt replaces the built-in prompt
and must include extractor.speech, extractor.conversation.last-10,
extractor.type_preamble, extractor.variables_list placeholders. Dates must be
anchored to the supplied now rather than any system clock; retain vague-date text
when the bank requires asking for an exact day.

All call variables live in one vars table, persist across nodes and can be stale.
Initialize/reset proposed-action and extracted-intent fields deliberately.
Templates use two opening/closing braces around variable_name in prompts/requests.
For JSON substitution use variable_name:json. Unset exact request placeholders can
drop a field; therefore initialize required values before invoking an API.
Do not use context_variables or an each_turn hook.

Every transition has target_node, description, condition. Intent:
{operator:matches_intent,description:...}. Unconditional: {operator:always}.
Variable comparisons must use an outer group:
{logic:or,conditions:[{variable:flag,operator:equals,operand:ready}]}.
Other comparisons: not_equals,greater_than,less_than,contains,is_set,is_not_set.
An outer group is always or; nested and/or groups are allowed. Boolean values
arrive as true/True strings. Do not put different conditional/unconditional routes
to the same target: the engine merges their conditions. An extracted enum can
route in the same turn. API response routing also runs without another user turn.

api_request/code nodes: on_enter silent, passthrough true,
passthrough_default_transition equal to the final fallback target, transitions
ending in always. pre_actions only on these node types. API pre_action uses the
supplied function template with handler __function__:api_call, fixed url/method,
headers.properties and body.properties with type/default leaves. config.timeoutMs
positive, maxRetries zero, connect_retries zero. Response mapping belongs on the
node: [{path:data.ok,variable:result_ok}, ...]. Tool results are an envelope with
status,data,message,status_code; ok inside data is the bank success flag. Strings,
objects/lists, and flattened keys may need defensive normalization. Never rewrite
success in a post-hook. Do not rely on a pre-hook exception blocking an API call.

code pre_action:
{type:function,function:{name:calculate,handler:__function__:code_exec,
parameters:{type:object,properties:{code:{type:string,default:PYTHON_SOURCE},
timeout_ms:{type:number,default:30000}}}}}.
Python has vars; values must be written to vars, not returned. Use only json,re,
datetime, bounded loops and supplied now. No files/network, real clock, exec/eval,
dynamic imports or double template braces in code (even nested dict endings).
Initialize string routing flags before try and fill fallback values in except.

end_call node: on_enter silent, transitions [], disable_inactivity_monitor true,
terminal {type:function,function:{name:finish,handler:__function__:end_call,
parameters:{type:object,properties:{message_mode:{type:string,default:none}}}}}.
Use a farewell conversation before the bank close API when required. The bank
close API must be the last bank tool, followed only by session termination.

Global nodes may interrupt normal nodes using condition/routing_prompt and
excluded_nodes; exclude terminals and guarded action sequences. Treat global
routes like normal graph edges, never allow them to bypass action prerequisites.
